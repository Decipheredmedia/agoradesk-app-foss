## 1. Prerequisites

| Requirement | Version / Notes |
|---|---|
| Flutter SDK | stable channel, `>=3.0.0 <4.0.0` (see `pubspec.yaml`) |
| Dart SDK | `>=3.0.0 <4.0.0` (bundled with Flutter) |
| Java (JDK) | 17 (Temurin recommended) |
| Android SDK | `compileSdkVersion 34`, `targetSdkVersion 34`, `minSdkVersion 23` |
| Android flavors | `agoradesk` (`com.agoradesk.app`) · `localmonero` (`co.localmonero.app`) |
| Branches | `main` — FCM-enabled builds · `fdroid_ad` — AgoraDesk FOSS · `fdroid_lm` — LocalMonero FOSS |

## 2. Required GitHub Secrets

Add all secrets in **Settings → Secrets and variables → Actions → New repository secret**.

### Existing secrets (used by `build_from_tags_ci.yml`)

| Secret | Description | How to obtain |
|---|---|---|
| `KEY_PROPERTIES` | Full content of `android/key.properties` (alias, passwords, store file paths for both flavors) | Created when generating keystores (see below) |
| `RELEASE_AGORADESK_KEYSTORE` | Base64+GPG-encrypted AgoraDesk `.jks` keystore | See "Keystore generation" below |
| `RELEASE_AGORADESK_KEYSTORE_SECRET` | GPG passphrase used to encrypt the AgoraDesk keystore | Chosen when encrypting |
| `RELEASE_LOCALMONERO_KEYSTORE` | Base64+GPG-encrypted LocalMonero `.jks` keystore | See "Keystore generation" below |
| `RELEASE_LOCALMONERO_KEYSTORE_SECRET` | GPG passphrase used to encrypt the LocalMonero keystore | Chosen when encrypting |
| `AGORADESK_GOOGLE_SERVICES_JSON` | `google-services.json` for the `agoradesk` Firebase project | Firebase Console → Project settings → Android app → download JSON |
| `LOCALMONERO_GOOGLE_SERVICES_JSON` | `google-services.json` for the `localmonero` Firebase project | Firebase Console → Project settings → Android app → download JSON |
| `FIREBASE_OPTIONS_AGORADESK` | Content of `lib/firebase_options_agoradesk.dart` | Generated by `flutterfire configure --project=<ad-project>` |
| `FIREBASE_OPTIONS_LOCALMONERO` | Content of `lib/firebase_options_localmonero.dart` | Generated by `flutterfire configure --project=<lm-project>` |
| `MAPBOX_KEY` | Mapbox public API token | [Mapbox tokens page](https://account.mapbox.com/access-tokens/) |
| `RELEASE_TOKEN` | GitHub Personal Access Token with `repo` scope for creating Releases | GitHub → Settings → Developer settings → PAT |

### New secrets (introduced by this runbook)

| Secret | Used by | Description | How to obtain |
|---|---|---|---|
| `PLAY_STORE_SERVICE_ACCOUNT_JSON` | `release_play_store.yml` | Google Play service-account JSON with **Release Manager** role | See §5 below |
| `FDROID_SIGNING_KEY` | `release_fdroid.yml` | Base64-encoded JKS key used by fdroidserver to sign the repo index | See §6 below |
| `FDROID_SIGNING_KEY_PASS` | `release_fdroid.yml` | Passphrase for the F-Droid signing key | Chosen when creating the key |

### Keystore generation

```bash
# Generate AgoraDesk keystore
keytool -genkeypair -v \
  -keystore agoradesk-keystore.jks \
  -alias adKeyAlias \
  -keyalg RSA -keysize 4096 \
  -validity 10000

# Generate LocalMonero keystore
keytool -genkeypair -v \
  -keystore localmonero-keystore.jks \
  -alias lmKeyAlias \
  -keyalg RSA -keysize 4096 \
  -validity 10000

# Encrypt and base64-encode for GitHub Secrets
gpg --symmetric --cipher-algo AES256 --batch \
  --passphrase "YOUR_SECRET_PASSPHRASE" \
  --output agoradesk-keystore.jks.gpg \
  agoradesk-keystore.jks
base64 agoradesk-keystore.jks.gpg   # → paste as RELEASE_AGORADESK_KEYSTORE
```

Set `RELEASE_AGORADESK_KEYSTORE_SECRET` to `YOUR_SECRET_PASSPHRASE`.

Example `android/key.properties` (value of `KEY_PROPERTIES` secret):

```properties
adKeyAlias=adKeyAlias
adKeyPassword=<ad_key_password>
adStoreFile=agoradesk-keystore.jks
adStorePassword=<ad_store_password>
lmKeyAlias=lmKeyAlias
lmKeyPassword=<lm_key_password>
lmStoreFile=localmonero-keystore.jks
lmStorePassword=<lm_store_password>
```

## 3. Release Workflow Overview

Three independent workflows trigger on the same `vX.Y.Z` tag push:

```
git push origin v1.2.0
         │
         ├─► build_from_tags_ci.yml   → Builds 4 APKs (ad, ad-foss, lm, lm-foss)
         │                               → Creates GitHub Release with APKs attached
         │
         ├─► release_play_store.yml   → Builds 2 AABs (ad, lm — FCM-enabled only)
         │                               → Uploads to Google Play (track: internal by default)
         │
         └─► release_fdroid.yml       → Builds 2 FOSS APKs (fdroid_ad, fdroid_lm branches)
                                         → Updates self-hosted F-Droid repo on `fdroid-repo` branch
```

The workflows are independent; a failure in one does not affect the others.

## 4. Step-by-Step: Cutting a Release

1. Update `version` in `pubspec.yaml` (format: `name+buildNumber`, e.g. `1.2.0+140`).
2. Update `RELEASE.md` with release notes for this version.
3. Update `distribution/whatsnew/en-US/default.txt` with Play Store release notes
   (max 500 characters per Google Play's limit).
4. Commit and push to `main`:
   ```bash
   git add pubspec.yaml RELEASE.md distribution/whatsnew/en-US/default.txt
   git commit -m "chore: bump version to 1.2.0+140"
   git push origin main
   ```
5. Create and push the tag:
   ```bash
   git tag v1.2.0
   git push origin v1.2.0
   ```
6. Monitor the three workflows in **Actions** tab. Each runs independently.
7. Promote from `internal` → `alpha` → `beta` → `production` in Google Play Console
   when ready (or re-run `release_play_store.yml` with `workflow_dispatch` and a
   different track).

To delete a tag and re-run:
```bash
git tag --delete v1.2.0
git push --delete origin v1.2.0
```

## 5. Play Store Setup (first time)

### Create a Google Play service account

1. Go to **Google Play Console → Setup → API access**.
2. Link to a Google Cloud project (or create one).
3. Click **Create new service account** → follow the Google Cloud Console link.
4. Create a service account, download the JSON key.
5. Back in Play Console, grant the service account **Release Manager** permissions
   for both `com.agoradesk.app` and `co.localmonero.app`.
6. Base64-encode the JSON and store as `PLAY_STORE_SERVICE_ACCOUNT_JSON`:
   ```bash
   cat play-service-account.json | base64 -w 0
   ```
   > **Note:** The workflow writes this value directly to a file; it must be the
   > raw JSON, not base64-encoded. Store the raw JSON as the secret value.

### First upload requirement

Google Play requires **at least one manual upload** before the API can push
subsequent releases. Upload the first AAB manually via Play Console → Create app
→ Internal testing → Upload, for each package (`com.agoradesk.app`,
`co.localmonero.app`).

## 6. Self-Hosted F-Droid Repo Setup (first time)

1. **Generate the F-Droid signing key:**
   ```bash
   keytool -genkeypair -v \
     -keystore fdroid.jks \
     -alias fdroid \
     -keyalg RSA -keysize 4096 \
     -validity 10000 \
     -dname "CN=FDroid, O=FDroid"
   base64 fdroid.jks   # → paste as FDROID_SIGNING_KEY secret
   ```
   Set `FDROID_SIGNING_KEY_PASS` to the keystore/key password you chose.

2. **Enable GitHub Pages** for this repository (Settings → Pages → Source:
   Deploy from branch → `fdroid-repo` branch, `/ (root)`).

3. **Add the repo URL in F-Droid client** on your device:
   ```
   https://<owner>.github.io/<repo>/
   ```
   or use the raw branch URL:
   ```
   https://raw.githubusercontent.com/<owner>/<repo>/fdroid-repo/
   ```

4. After the first successful `release_fdroid.yml` run, the `fdroid-repo` branch
   will contain the signed index and APKs.

> **Note:** The F-Droid signing key is separate from the Play Store release
> keystores. Keep the `fdroid.jks` file backed up securely; if lost, users will
> need to uninstall and reinstall to accept updates from a new key.

## 7. Official F-Droid Submission (one-time)

The official F-Droid build server builds apps from source using metadata recipes
in [fdroid/fdroiddata](https://gitlab.com/fdroid/fdroiddata). This process is
**not automated** by this repo's CI — it is a one-time community contribution.

1. Fork [fdroid/fdroiddata](https://gitlab.com/fdroid/fdroiddata).
2. Copy `fdroid/metadata/com.agoradesk.app.yml` from this repo to
   `metadata/com.agoradesk.app.yml` in your fork. Create a corresponding
   `metadata/co.localmonero.app.yml` for LocalMonero.
3. Open a merge request against `fdroid/fdroiddata`.
4. After acceptance, F-Droid will build and publish automatically on each new
   tagged release matching the `UpdateCheckMode`.

## 8. Troubleshooting

### Keystore / base64 corruption

**Symptom:** `gpg: decryption failed: Bad session key` or
`java.io.IOException: Invalid keystore format`

**Fix:** Re-encode the keystore. The `decrypt_secret.sh` script uses GPG
symmetric encryption. Ensure the passphrase in the secret exactly matches the
one used to encrypt. Re-generate:
```bash
gpg --symmetric --cipher-algo AES256 --batch \
  --passphrase "EXACT_PASSPHRASE" \
  --output keystore.jks.gpg keystore.jks
base64 keystore.jks.gpg
```
Paste the output (no trailing newline) as the secret.

### Mismatched versionCode / versionName between flavors

**Symptom:** Play Console rejects the upload with "Version code already used" or
"Version code is lower than the highest version code".

**Fix:** Both flavors share the same `versionCode` from `pubspec.yaml`
(`version: name+buildNumber`). Increment the build number on every release.
Check `android/app/build.gradle` — `versionCode` and `versionName` are read from
`local.properties` which is populated by the Flutter Gradle plugin from
`pubspec.yaml`.

### Play Console app not yet created

**Symptom:** `Upload failed: App not found: com.agoradesk.app`

**Fix:** The app must exist in Play Console before the API can upload to it.
Perform the first upload manually (see §5).

### F-Droid reproducible-build failures

**Symptom:** F-Droid build server rejects the build or produces a different APK hash.

**Cause:** `pubspec.yaml` includes a git-based dependency override
(`flutter_socks_proxy` pinned to a git commit). F-Droid's build server needs
network access to that git repository. Additionally, Flutter submodule versioning
must match exactly.

**Fix for self-hosted repo:** This is not an issue — CI builds and signs the APKs
directly. For official F-Droid submission, pin the git dependency to a specific
commit and document it in the metadata recipe's `srclibs`.

### Missing google-services.json causing Firebase init crash

**Symptom:** FCM-enabled builds crash on startup with
`Default FirebaseApp is not initialized`.

**Cause:** The `google-services.json` secrets (`AGORADESK_GOOGLE_SERVICES_JSON`,
`LOCALMONERO_GOOGLE_SERVICES_JSON`) are empty or malformed.

**Fix:** Download fresh copies from Firebase Console → Project settings →
Android app. Ensure the `package_name` in the JSON matches the flavor's
`applicationId` (`com.agoradesk.app` / `co.localmonero.app`). FOSS builds
(`-foss`) do not use Firebase and are not affected.

### `distribution/whatsnew` too long

**Symptom:** Play Store upload fails with "Release notes are too long".

**Fix:** Google Play limits release notes to **500 characters per locale**.
Edit `distribution/whatsnew/en-US/default.txt` and keep it under 500 characters.
